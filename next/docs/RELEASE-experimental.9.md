# 1.3.0-experimental.9

新增独立的 `test-room` 模块：多个 Agent 可以在本地联机中使用指定武将，并固定
斗地主身份或 2v2 队伍，不再依赖随机候选恰好出现目标武将。

- `test-room create NAME --lineup FILE` 读取 JSON 阵容，创建房主与全部独立客机。
  `start` 校验各端内容、完成原生选将并核对全端武将与阵营；`status/close` 查看和清理。
- 房主只在内存中适配已识别的原生选将流程，保留引擎初始化和同步，游戏安装文件只读。
  开局过程失败会记录原因并关闭所拥有的测试客户端，避免把部分成功当成有效测试。
- 测试房使用软件渲染，缓解本机多客户端启动时遇到的 GPU 故障；普通房间启动行为不变。
- 更新 `noname-play`：主文档保留简短入口，完整工作流放在
  `references/test-room.md`；补充房主和客机各自的清理职责。
- ZIP 新增阵容示例和完整 `skills/noname-play`，可直接复制到 Agent 技能目录。

验证：配置匹配引擎后，612 项自动化测试全部通过。子琪 v1.11.3 实测完成标准
斗地主、固定队伍 2v2、洛妃＋鲜血樱华＋曹操的三组开局，全端武将和阵营一致。
房主和客机可继续通过原有玩家接口观察。普通樱华因原生 `forbidai` 限制，在开始
游戏前被拒绝；没有随机换将。

这次验证的是固定阵容开局，没有完成整场模型对战或穷举自制技能。暂不支持双人
1v1、双将、重复武将或绕过原生禁选。座次、先手和牌堆仍不固定；2v2 指定队伍
可能改变原生随机组队的相邻队友布局。官方版房间初始化、联机客机日志覆盖及
既有 2v2 停顿限制仍保留。

详见 [测试房](TEST-ROOM.md) 和 [验证范围](VALIDATION.md)。ZIP 不包含游戏本体、
模型、本机配置、运行状态或原始对局记录。
