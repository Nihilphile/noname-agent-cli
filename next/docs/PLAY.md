# play 混合操作串（experimental.5.1）

`play` 执行预先给出的有限操作串。原始操作和完整用牌可混合；规则与合法性由原游戏决定。
原 `act` 和 `act` 计划语义保持原样。

```powershell
node bin/noname.cjs play "无中 | 顺[殷华] > 诸葛连弩 > 杀【♥8】[殷华] > c308[fp3]" --at REV
node bin/noname.cjs play "act(b12) > act(b19) > act(confirm) | 顺[殷华]" --at REV
```

PowerShell 中必须引用整个表达式，避免 `|` 和 `>` 被 shell 解释。
可用 `--stdin` 读取纯文本表达式；`--seconds` 为整串执行时限（1..60 秒）。
每次底层动作之间默认至少间隔 500 毫秒（`--interval-ms`，范围 0..5000）；
封装内部的选牌、目标和确认也遵守此间隔。间隔后重新观察，仍在结算则等待可操作选择，
直到整体时限；固定延迟不代表动画已完成。间隔计入整体时限。

可加 `--wait [--wait-seconds 15]`：所有步骤已证实成功后，用独立的 1..60 秒预算等待下一选择、本人死亡或终局。已有选择立即返回，失败或中途暂停不追加等待。`--seconds` 只管执行，`--interval-ms` 只管操作间隔；三者不混用。

```powershell
node bin/noname.cjs play "act(b12) > act(b19)" --at REV --seconds 30 --interval-ms 500 --wait --wait-seconds 15 --log-mode experimental
```

同一次反馈包含串内操作及等待期间已采集的日志，内部点击/观察不推进游标。最后只确认并提交最终反馈一次；若等待观察失败，保留成功步骤、标记快照过期，不消耗日志游标。详见 [动作与等待合并](ACT-WAIT.md)。

## 连接与结果

- `>`：前一步成功才继续；`|`：前一组明确成功或失败后，继续下一组。
- `>` 优先级更高。`A > B | C > D` 中 A 失败跳过 B，仍执行 C；C 失败跳过 D。
- 原始步骤成功（`1`）只表示该次底层动作已接受，不代表整个技能发动完成。
- 用牌步骤成功（`1`）必须有本次实体牌的提交证据；被闪、被无懈不改变提交成功。
- 明确不匹配或动作被拒绝为 `0`。等待未写明的补充选择、结果未知、换局、过期凭据等整体停止，不能当普通失败沿 `|` 继续。
- 输出逐项成功/失败/跳过，实际尝试的实体牌 ID，当前状态和未执行的剩余指令。部分失败必须在整体结果中可见。
- 已执行步骤不会重放或回滚。暂停后先用 `act` 处理问题，再根据新状态和剩余指令显式调用 `play`；没有自动恢复令牌或后台续跑。

## 原始操作

`act(ID)` 精确匹配当前可见选项或 `confirm` / `cancel`。允许现有底层请求的
`--unselect`、`--value VALUE`、`--to ID` 参数；不解释技能名或推导技能决策。
参数写在完整表达式内，例如 `act(b12 --value 2)`；不是 `play` 的外层参数。
每步使用最新 revision 执行，不能仅凭旧 ID 绕过当前选择检查。
预先写明且匹配的技能按钮、子选项、确认可连续推进；未写明的询问不会自动回答。
原始动作按原 `act` 的行为保留选择；失败后续组看到的就是当前实际状态。
跨选择的通用确认/取消必须能绑定到本串明确开始的交互，不能误答插入的无关询问。

## 完整用牌

语法为 `牌名或实体ID【可选花色点数】[可选目标]`。
多个明确目标用逗号分隔，按书写顺序选择；无目标的牌可以省略方括号。
省略目标不授权随机选目标。缺少必要目标时返回待补充选择。

- 标准牌名/内部名精确匹配；明确简称见实现的简称表（至少支持无中、顺、杀、诸葛连弩）。不猜错别字。
- `顺`：从当前自己手牌的所有匹配实体牌中随机选一张，不预筛成可点击牌。
- `顺【♠3】`：附加花色点数匹配；`c308`：只匹配此实体牌。
- 每步执行时才匹配手牌，允许使用前一步刚摸到的牌。
- 选定后固定实体牌；不因不可选、目标非法而换牌试探，不模拟距离或规则。
- 目标按角色 ID 或明确名称匹配；同名歧义失败，不能随机消歧。
- 封装只用于自己出牌阶段直接使用实体手牌。技能转化牌与回合外响应使用原始 `act(...)`。
- 封装处理选牌、选目标和必要确认；兼容原生自动确认。确认是否需要，以当前选择和提交证据为准。
- 提交前明确失败时，只撤销本步骤新增的选择，并确认清理完成后才允许 `|` 继续；进入时已有未完成选择则停止，避免混入既有操作。
- 顺手牵羊提交后的拿牌询问、技能插入询问等若下一步未明确提供可匹配的原始操作，暂停并返回当前问题及剩余串。
- 引擎只表明不可选时，报告当前不可选，不虚构距离、次数等原因。

## 接口与验证

experimental.5.2 的联机客机复用同一执行器。`room` 在房主和客机内安装运行时适配器：房主给选择提供阶段/请求标识，并仅向该玩家发送直接实体牌的接纳回执；客机将原生实体 ID 映射回自己的卡牌 ID。完整用牌必须匹配当前请求和房主回执，不能把 WS 已发送、UI 已确认或手牌消失当作成功。`steps[].submission.confirmation=host_accepted` 只证明提交，不证明所有效果已结算；客机效果完备性仍为未知。没有回执时停止且不自动重放，`|` 也不能跨过结果未知。需要通过新版 `room create` 创建房间。

核心模块 `src/play.cjs` 导出 `parsePlay(text)`、`executePlay(plan, adapter, options)`。
适配器复用 `observe()`、`act(request)`、`effects()`、`sleep(ms)`；options 包含 `at`、`timeoutMs`、`intervalMs`（默认500），可注入随机源以验证选牌。CLI 在 `--wait` 时传入 `deferFinalWait:true`，将成功后的等待交给共享 `waitAfterAction`。
返回对象固定 `kind: 'play'`，包含 `ok`、`status`、`value`（1/0/null）、`steps`、`state`、`remaining`；错误保留 code/message。
单步记录包含原始表达式、status、value 和实际动作/卡牌信息。
整串执行结束时，只要有明确失败就为 ok=false/value=0，即使后组成功也不隐藏失败。
若后续遇到未完成询问、超时或结果未知，整体为 paused/value=null；steps 仍保留此前每项的 1/0，不能把暂停当成已经执行完的普通失败。
执行必须有时限、步数上限、初始 revision 和全过程 epoch 校验；异常提交不能自动重放。
当前页面只为出牌阶段提供稳定 phaseId；play 会在 phaseId 改变时停止。`--wait` 有一项边界例外：全部步骤已证实成功时，允许最后一步自然引发的阶段变化，并将快照交给尾随等待；这不授权执行跨阶段的下一项指令。其他原始操作依赖当前选项、epoch 与询问归属校验，不声明所有非出牌阶段都有独立的阶段实例校验。
CLI 沿用动作锁、操作证据、通知确认和增量日志提交；旧 `act` 回归必须通过。

验收覆盖连接优先级、原始技能链、即时摸牌后匹配、随机固定、目标歧义、目标失效清理、自动确认、额外选择暂停、过期凭据/换局/结果未知，以及原 `act` 回归。实机使用独立会话名；支持隔离环境及用户授权的原客户端，结束时停止自有会话并保留原客户端 profile，不修改引擎文件或擅自更改游戏规则设置。
