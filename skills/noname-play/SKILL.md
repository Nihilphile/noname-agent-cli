# 无名杀游玩

把自己当作正在看界面、作选择的玩家。CLI 是观察和执行界面，不是决策来源；先理解局面、形成计划，再用尽量少的交互完成已经决定的行动。

先找到用户指定的工具目录：包含 `bin/noname.cjs` 和 `package.json` 的目录（源码仓库为 `next/`，发布 ZIP 为解压根目录）。以下命令均在该目录运行，并沿用用户指定的 session。`NAME`、`REV`、`PLAYER` 等是占位符。

接手已有会话时直接观察；只有用户要求启动、重开、选择客户端、加载可选内容或管理房间时，才读[会话与内容配置](references/sessions.md)。

用户要求多个 Agent 使用指定武将对战，或固定联机身份/队伍时，先读[固定阵容测试房](references/test-room.md)。已分配好 session 的参与者直接按下文游玩。

```powershell
node bin/noname.cjs observe --detail --session NAME
```

确认自己的角色、胜利条件、手牌、装备、体力、行动顺序、合法可见的队友信息、当前选择和新增战报。牌面不可见时只使用数量或位置；区分已知、推测与未知。

## 滚动规划

每次取得反馈后执行同一个循环：

1. **观察局面**：先处理当前选择，确认会立即改变胜负、存亡、目标合法性或资源价值的事实。
2. **拟定计划**：为当前询问或出牌阶段形成一个暂定的完整计划，而不是只想下一次点击。
3. **寻找再规划点**：判断哪些动作的结果可能改变后续动作、目标、资源投入、行动顺序或是否继续。
4. **提交承诺前缀**：把已经决定的最长操作链交给 `play`，执行到并包含产生第一个再规划点的动作，不预写依赖该结果的后续动作。
5. **吸收结果**：读取已完成步骤、最终状态和新增战报；在再规划点重新制定计划，不重放已经提交的动作。

再规划点位于决策相关结果出现之后。它不是“产生了新信息”，而是“新信息可能改变剩余计划”。一个动作即使产生伤害、响应或日志，只要这些结果不会改变承诺前缀中的下一步，就可以继续执行，结束后再统一吸收。

例如，无中生有摸到的新牌通常可能改变整个出牌顺序，因此先只使用无中生有。重新观察后，如果新牌不改变原计划，可以把确定的后续行动合并：装备减一马、顺走敌方公开防具、装备该防具、对既定目标出杀、装备木牛流马。若木牛中放什么牌或是否交给队友仍需“看情况”，承诺前缀就在装备木牛后结束。

陌生技能、未知手牌、伤害结果和新询问不必一律阻断操作链。只有它们的合理结果可能让你改变下一步时，才提前停下；如果它们对下一步无关，继续执行既定计划。

## 决策不变链

当询问次数未知、但每次答案已经相同时，按规则允许的上界预写重复操作，让不存在的下一步自然截断。

例如殷潮移除3个标记后会翻开3张牌，其中每张红牌产生一次杀。如果已经决定所有这些杀都以 A 为目标，就按当前可见选项 ID 预写“结束回合 → 移除3个标记 → A → A → A”：

- 3张红牌时，三个目标操作全部执行。
- 1张红牌时，第一个目标执行，第二个目标选项不存在，链在此停止。
- 没有红牌时，第一个目标操作就不存在，技能结算后停止。
- A 不再是合法目标时停止，不擅自换成其他角色。

这种截断是预期的机械边界。返回可能包含失败步骤，但此前已经完成的结束回合、技能选择和出杀仍然有效；按完成步骤和当前状态继续，不能把整条链重放。

如果第一次杀的结果可能让你改打 B、停止出杀或改变资源投入，那么目标并非决策不变，应在该结果处重新规划。`play` 负责选项存在性、合法性和插入询问等机械不确定性；你负责判断新信息是否改变策略。

## 执行计划

所有局内有状态动作都通过 `play` 命令提交，即使承诺前缀只有一步。实体牌使用、响应、救援和弃牌时，让 `play` 完成选牌、目标和必要确认；主动技能、转化牌、未支持的按钮选择和反选等原始操作写成 `play "act(OPTION)"`。这里的 `act(...)` 是操作串内部语法，不是普通游玩时直接调用 `act` 命令的入口。

已经决定且属于同一承诺前缀的动作使用 `>` 连接。已知普通锦囊后续选牌可写 `拆[PLAYER<诸葛连弩>]` 或 `顺[PLAYER<藤甲>]`，无需等待按钮 ID。其他尚不能表达的后续操作，在新询问出现后用新 revision 继续；不能因此退化为逐点击规划。

```powershell
node bin/noname.cjs play "杀[PLAYER]" --at REV --wait --session NAME
node bin/noname.cjs play "青龙偃月刀 > 杀[PLAYER]" --at REV --wait --session NAME
node bin/noname.cjs play "act(OPTION)" --at REV --wait --session NAME
node bin/noname.cjs wait --seconds 10 --session NAME
```

第一次使用嵌套选牌、实体 ID、空目标 `[]` 或弃置/展示/打出语法，编写复杂操作串、需要 `|` 失败分支、数值/移动操作，或操作链暂停时，读[操作串规则](references/play.md)。保留以下边界：

- 使用最新 revision；`stale_choice`、结果未知或观察失败时先重新观察。
- 中途出现未预期询问时，让操作链暂停；处理新决定后只提交仍需要的剩余部分。
- 选项缺失造成的预期截断可以结束决策不变链；有副作用的部分失败必须按返回状态处理。
- 操作串中 `act(...)` 的点击成功不等于整次用牌已经结算。只使用当前反馈中实际存在的目标、确认或取消。
- 正常等待超时表示当前仍在结算或等待其他角色，不表示动作没有发生，也不授权重放。

根据状态继续：

| 状态 | 处理 |
| --- | --- |
| `choice` | 理解提示和合法选项，重新规划并用最新 revision 执行 |
| `running` | 用 `wait` 等待下一选择或结算，不重复上一动作 |
| `dead` / `over` | 记录本人死亡或原生终局，结束本次参与 |
| `setup` / 连接错误 | 查 `status` / `diagnose`，确认客户端状态后恢复 |

## 查规则与复盘

遇到会影响当前计划的陌生技能或卡牌时按需查询：

```powershell
node bin/noname.cjs inspect PLAYER skills --session NAME
node bin/noname.cjs rule SKILL_OR_CARD_ID --session NAME
```

用合法选项判断可执行范围，用规则解释选择的意义。战报是已经发生之事的证据：受伤、体力流失、回复和护盾吸收是不同事实；牌转移不等于自愿给牌；重复显示的同序号日志不代表动作再次发生。需要精确格式、数量选择、卡牌整理、订阅或高级诊断时，再查工具目录的 README 和相关 docs，不在普通游玩循环中加载整份工具手册。

## 结束与交回

按用户约定的局数和终点行动。默认以本人死亡或原生 `over` 先到者结束参与；未观察到最终胜负时明确写“最终胜负未观测”。简述关键决策、结果和仍不确定的信息，不用规则推测补成已经发生的事实。

普通会话在结束后用 `stop --session NAME` 清理；房间会话按对应 reference 的房主/客机约定交回或清理。用户要求保留窗口时按约定处理。
