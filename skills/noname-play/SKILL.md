# 无名杀对局

把自己当作正在看界面、作选择的玩家。先处理当前选择，再用新增战报理解刚才发生的事。
默认用 `play` 执行已决定的完整动作，在需要新信息作判断的地方停下来。

先找到用户的工具目录：包含 `bin/noname.cjs` 和 `package.json` 的目录（源码仓库为 `next/`，发布 ZIP 为解压根目录）。以下命令均在这个目录运行；
使用用户指定的工具目录时，以其实际入口和 `help` 支持的命令为准。`NAME`、`OPTION`、`REV` 等是占位符。
用户要求启动、重开、选择客户端或加载可选武将包时，先读[会话与内容配置](references/sessions.md)；
接手已经运行的会话无需加载该参考，直接观察。

## 进入对局

沿用用户指定的 session；新局使用独立名称。接手已有对局先观察，用户要求开新局时才启动。
新局启动方式或可选武将不清楚时，查 `node bin/noname.cjs help`；启动异常再用 `doctor`。
通过 CLI 操作并保持引擎文件不变；原生客户端沿用用户配置，隔离客户端使用该会话自己的内容配置。

第一次进入会话：

```powershell
node bin/noname.cjs observe --detail --session NAME
```

确认自己的角色、阵营、手牌、合法可见的队友信息，以及当前选择。
日志模式沿用用户要求或工具配置；需要实验日志时，在命令上加 `--log-mode experimental`。
后续通常用普通反馈：自己出牌阶段首个决策会显示局面，同阶段后续省略重复概览，别人回合需要响应时会显示。想补看全场时用 `observe --state_show`，需要技能和标记详情才用 `observe --detail`。

## 根据反馈继续

| 当前状态 | 下一步 |
| --- | --- |
| `choice` | 读提示、选择数量与合法选项，按下方原则决定完整动作或操作串，用最新 revision 执行 |
| `running` | 已无当前选择，等待其他角色或结算继续 |
| `dead` / `over` | 记录本人死亡或原生终局，结束本次参与 |
| `setup` / 连接错误 | 查 `status` / `diagnose`，确认客户端状态后恢复 |

### 优先用 play 执行已决定的动作

- 自己出牌阶段直接使用实体手牌，即使只出一张，也优先用 `play "杀[PLAYER]"`，由工具完成选牌、目标和必要确认。
- 连续动作的牌与目标已经决定，且后续决策不依赖中间结果时，合并为一个 `play`。例如已决定装备武器后出杀，可用 `play "青龙偃月刀 > 杀[PLAYER]"`。
- 主动技能、转化牌和回合外响应使用原始选项；已知的连续交互可用 `play "act(ID1) > act(ID2)"` 合并。只有一个选项要点时，直接 `act` 即可。
- 陌生交互先单步确认流程；本局后续相同交互，若选项和目标已明确，主动组合。是否停下来取决于有没有新的决策，而非有没有下一次点击。
- 若后续选择取决于新摸的牌、展示的手牌、伤害结果或新的技能询问，就在该处停下来判断。例如无中后需要重新选牌或目标时，先只执行 `play "无中"`。

常用的操作与等待（替换示例中的 PLAYER、OPTION 和 REV）：

```powershell
node bin/noname.cjs play "杀[PLAYER]" --at REV --wait --wait-seconds 15 --session NAME
node bin/noname.cjs play "青龙偃月刀 > 杀[PLAYER]" --at REV --wait --wait-seconds 15 --session NAME
node bin/noname.cjs act OPTION --at REV --wait --wait-seconds 5 --session NAME
node bin/noname.cjs wait --seconds 10 --session NAME
```

`act` 和 `play` 都支持 `--wait`：动作或整串成功后等待下一选择、本人死亡或终局；已有选择立即返回。
失败或暂停时跳过尾随等待，不会替你选择下一张牌或目标。`--wait-seconds` 默认 15 秒、范围 1..60，独立于操作串的 `--seconds` 执行预算。
正常等待超时表示动作已成功、当前仍 `running`，之后用 `wait` 或订阅继续，不能重放。
等待观察失败时，保留的成功步骤仍有效，但快照已过期；先 `observe` 核实。`stale_choice` 同样先取得新凭据。

**选中不等于提交。** 原始 `act` 的“动作已完成”只说明本次点击完成；牌显示“已选”后，可能还要
选目标或确认，也可能因原生自动确认已经结算。
单步 `act` 后或操作串暂停时，看返回的新提示和选项。桃等自用牌可能直接提交，不能习惯性追加自己的 ID 或 `confirm`。
只在返回中存在且当前确实需要时使用确认、取消。

底层 `act` 组合中途失败会保留已完成步骤：例如杀已选中、目标不可用，先重新评估返回的合法目标，选择合适目标；
若没有合适目标就反选已选的杀。合法目标可能包含队友，不要随意选取，也不要重复选牌。
需要反选时，按当前反馈使用 `act ID --unselect --at REV`。

## play 语法与暂停恢复

用 `play` 合并明确的完整用牌和原始操作；整串加引号，让 PowerShell 保留 `>`、`|`。
完整用牌如 `顺[PLAYER]`、`杀【♥8】[PLAYER]`、`c308[PLAYER]`，负责选牌、目标和必要确认。
主动技能、转化牌和回合外响应使用当前可见选项的 `act(ID)`，如 `act(b12) > act(b19)`；技能没有名称语义封装。
示例中的 ID 和 PLAYER 必须替换为本局已知选项及明确目标。第一次写串或遇到暂停时，读 [操作串规则](references/play.md)。
原始选项 ID 可能在动作后变化，后续 ID 必须有当前交互依据。重复 `act(PLAYER)` 仅按选项匹配，
不保证限定在同一次技能结算内；需要“本次技能结束就返回”的重复操作时，按实际返回的询问续接。

- `A > B | C`：A 成功才执行 B；A 或 B 明确失败后仍尝试 C。`|` 不能越过未知结果或未写明询问。
- 每步底层动作后默认留 500ms 动画间隔并重新观察；`--interval-ms` 调整间隔，时间计入 `--seconds`。
- 中途插入需要你作答的新询问时，读取当前问题和 `remaining`，先处理后再显式提交剩余串；已完成步骤不重放。
- 成功执行最后一步后可以进入下一阶段并由 `--wait` 返回新选择；这不允许继续执行跨阶段的下一条预写指令。

## 查清影响当前决定的规则

遇到影响当前目标、响应或伤害判断的陌生技能，按需查：

```powershell
node bin/noname.cjs inspect PLAYER skills --session NAME
node bin/noname.cjs rule SKILL_OR_CARD_ID --session NAME
```

用当前提示和合法选项判断可操作范围，用规则解释这些选择的意义。
牌面不可见时只知道数量或位置，不能据此补出暗牌内容；没有记录的效果也不能当作没有发生。

## 读实验战报

- 轮次、回合和阶段标题给出时间位置。裸 `{…}` 始终属于当前回合持有者；
  其他角色写成 `乙 {…}`。夹入乙的行动后，下一段裸组仍属于回合持有者。
- 状态 `（…）` 也属于当前回合持有者；其他角色显示为 `乙（…）`。只有相邻、同一承受者且同阶段的状态会合并。
- `杀‹闪【♥9】›[乙]` 表示使用杀，公开材料是该张闪，目标是乙；`打出` 表示响应。
  `技能·选目标[乙]` 是实际选择，不是又发动一次技能。借刀等有主次含义的目标按提示理解。
- `牌转移：甲→乙` 说明牌从甲到乙，不说明甲自愿给牌。只写数量时，牌面尚未提供。
- 五谷先以“展示”给出公开牌池，各角色后续的“获得”记录给出他实际取走的公开牌；按时间顺序阅读，不从普通获得数量猜牌面。
- 受伤、体力流失、回复、护盾吸收是不同事实。组里的状态承受者不一定是行动者；
  同一组也不保证所有变化都由组首操作造成。
- 多步 `play` 的内部操作和观察不消耗日志；最终反馈包含本次调用中已采集的插入技能、响应及尾随等待日志。
  未写明询问使串暂停时，也会带回截至暂停的已采集记录。实验日志有捕获边界及每路 2000 条缓冲上限；按截断标记判断缺段，不当作无限完整历史。
- `observe` / `wait` 读过的日志可能在下一次 `act` / `play` 再出现。按同一路日志序号识别新尾段，
  不把重复显示当成再次执行；换局后的序号重新开始。

## 结束与交回

按用户约定的局数和终点行动。默认以本人死亡或原生 `over` 先到者结束本次参与；
本人死亡时未见最终胜负，就写“最终胜负未观测”。
简述关键操作和仍不确定的信息，不用规则猜测补成已经发生的事实。

自己负责的会话在结束后用 `stop --session NAME` 清理；任务要求交回会话或保留窗口时，
按约定处理。重开需要符合用户给定的局数或新的开局要求。

遇到数量选择、卡牌整理、订阅或更复杂组合时，再按当前需求查工具目录的
`README.md` / `docs/NOTIFICATIONS.md`，不在普通出牌循环里加载全部说明。
