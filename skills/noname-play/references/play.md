# play 操作串

命令在 SKILL.md 指定或用户指定的工具目录执行。换用其他版本时先查 `help` 是否支持 `play --wait`。

```powershell
node bin/noname.cjs play "无中 | 顺[fp3] > 杀【♥8】[fp3]" --at REV --wait --session NAME --log-mode experimental
node bin/noname.cjs play "act(b12) > act(b19)" --at REV --seconds 30 --interval-ms 500 --wait --wait-seconds 15 --session NAME
```

例子只示范语法，REV、目标和选项 ID 要来自实际反馈。先决定合法操作，再组合；不能靠试点探测规则。

## 用牌与技能

完整用牌仅用于自己出牌阶段直接使用实体手牌。支持明确牌名/简称、花色点数或实体 ID；不猜错别字。多个目标如 `c308[fp3,fp4]`，按书写顺序选择。

省略实体 ID 时，在执行到该步的当前手牌里匹配并随机固定一张；允许使用前一步新摸的牌。固定后不可用则失败，不换另一张试探。省略目标不授权随机选目标；目标有歧义或缺失时按反馈补充。

`act(ID)` 复用底层操作，可写 `act(ID --unselect)`、`act(ID --value 2)`、`act(ID --to TARGET)`；具体参数取决于当前选项。技能链只预写已知且能匹配的原始操作，不推导技能名或替玩家决策。通用 `confirm` / `cancel` 必须属于本串已开始的交互，不能用来回答插入的无关询问。

## 结果与继续

`>` 比 `|` 优先。`A > B | C > D` 中 A 明确失败会跳过 B，仍尝试 C；C 成功才执行 D。

| 返回 | 下一步 |
| --- | --- |
| 单步 `1` | 原始操作表示点击已接受；完整用牌表示有该实体牌的提交证据。被闪或无懈仍算已提交 |
| 单步 `0` | 明确不匹配或被拒绝，依 `>` / `|` 规则继续；整串最终仍为失败，即使后组成功 |
| 暂停 / `value=null` | 读当前问题、失败码及 `remaining`；处理问题并取得新 revision 后，只显式提交仍需要的剩余步骤 |
| 结果未知 / 换局 / 快照过期 | 先观察核实，保留此前成功证据，不把未知当作 `0` 或重放已提交动作 |

完整用牌提交前失败，会只清理本步骤新增的选择，确认清理后才沿 `|` 继续；原始 `act(...)` 失败则保留实际选择状态。进入时已有未完成选择，先处理它，再调用完整用牌。

顺手拿牌、技能插入等补充询问未在串中明确给出时会暂停。只要还有下一步预写指令，阶段变化也会停止串；最后一步已证实成功且带 `--wait` 时，可以交回下一阶段的选择。

## 三种时间

| 参数 | 用途 |
| --- | --- |
| `--seconds` | 操作串执行预算，默认 30 秒、范围 1..60 |
| `--interval-ms` | 每个底层动作后的动画间隔，包括完整用牌内部的选牌/目标/确认；默认 500ms、范围 0..5000，计入执行预算 |
| `--wait-seconds` | 仅随 `--wait` 使用；整串成功后的独立等待预算，默认 15 秒、范围 1..60 |

固定间隔不保证动画完成，工具会重新观察。`--wait` 只观察，不回答新选择、不自动续跑 `remaining`。整串有失败或暂停时返回 `wait.status=skipped`。

等待结束读 `wait` 与操作串结果两部分：`ready` 返回选择/死亡/终局；`timeout` 表示已成功但仍 running；`error` 表示动作已完成而当前状态无法确认，先观察且不能重放。已有选择时 `ready` 的等待耗时可为 0，并不证明发生过额外轮询。

需要更精确的错误或日志语义时，查当前工具目录的 `docs/PLAY.md`、`docs/ACT-WAIT.md`。
